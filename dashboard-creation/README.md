# Member 3 – Dashboard Creation

## 1. Purpose

The purpose of this module is to develop an interactive dashboard for the **Causal Inference & Synthetic Control Engine for Algorithmic Pricing** project. The dashboard presents the results of Synthetic Control analysis in a clear and understandable format using charts, tables, and summary metrics.

It allows users to compare actual performance with synthetic control estimates and understand the impact of a pricing intervention.

## 2. Technologies Used

- **React.js:** Builds the interactive dashboard interface.
- **JSX (HTML-like syntax):** Defines the dashboard structure, including navigation, cards, tables, and content sections.
- **CSS:** Styles the dashboard layout, sidebar, colors, spacing, tables, and charts.
- **JavaScript:** Handles user interactions and frontend logic.
- **Python Flask:** Provides backend API endpoints for the dashboard.
- **Pandas:** Reads and processes CSV analysis results in the backend.
- **Flask-CORS:** Enables cross-origin requests between the React frontend and Flask backend.
- **NumPy:** Supports numerical operations used in the analysis.
- **SciPy:** Provides optimization functionality used by the analysis.
- **Matplotlib:** Supports plotting where used by the Python analysis.

## 3. Main Files

- `my-app/src/App.jsx` – Contains the React dashboard components and JSX structure.
- `my-app/src/App.css` – Defines the dashboard's appearance and layout.
- `backend/app.py` – Provides the Flask backend API used to retrieve analysis results.
- `backend/requirements.txt` – Lists the Python packages required by the backend.
- `my-app/package.json` – Lists the frontend dependencies and available scripts.

*Note: Adjust file paths if your project uses a different folder structure.*

## 4. Dashboard Features

The dashboard includes the following features:

1. **Summary Metrics:** Displays key results from the Synthetic Control analysis.
2. **Revenue Analysis:** Compares actual revenue proxy values with synthetic control estimates.
3. **Sales Analysis:** Displays actual and synthetic sales trends.
4. **Donor Region Weights:** Shows the contribution of donor regions to the synthetic control.
5. **Placebo Test Results:** Presents the results of placebo analysis.
6. **Analysis Data:** Displays analysis-ready data retrieved through the backend API.
7. **Interactive Interface:** Provides navigation and a structured layout for exploring the results.

## 5. Dashboard Data Flow

The dashboard works through the following process:

1. The causal analysis module generates CSV output files.
2. The Flask backend reads the required CSV files using Pandas.
3. Flask API endpoints return the analysis results to the React frontend.
4. React uses JavaScript to process the API responses.
5. JSX defines how the information is displayed, while CSS controls its appearance.
6. The dashboard presents the results through summary metrics, charts, and tables.

## 7. How to Run the Dashboard

### Start the Flask Backend

Open a terminal in the project directory and navigate to the backend directory:

```bash
cd backend
```

Install the required Python packages:

```bash
pip install -r requirements.txt
```

Start the backend:

```bash
python app.py
```

Keep this terminal running. The backend URL and port depend on the configuration in `app.py`.

### Start the React Frontend

Open a second terminal and navigate to the React application directory:

```bash
cd my-app
```

Install the frontend dependencies:

```bash
npm install
```

Start the frontend:

```bash
npm run dev
```

If your project uses Create React App, use `npm start` instead when configured in `package.json`.

Open the local URL displayed in the terminal to access the dashboard.

## 8. Dashboard Testing

The dashboard should be tested to verify that:

- The React frontend starts successfully.
- The Flask backend runs without errors.
- The frontend can retrieve data from the backend API.
- Required CSV files are available at the paths expected by the backend.
- Summary metrics, charts, and tables display the returned data correctly.
- Missing data or backend errors are handled appropriately.
